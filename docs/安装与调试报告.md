## 三、调试过程与修复的三个问题

### 问题 1：netchop 默认临时目录不存在

**现象**
```
Error. Cannot make tmpdir. Exit
```

**原因**：启动器里 `TMPDIR` 默认写死为 `/scratch`，该系统上不存在。

**已修复**：`/opt/bio/netchop-3.1/netchop` 中改为 `/opt/bio/netchop-3.1/tmp`。

---

### 问题 2：netMHCpan `-pmhc` 必然失败（厂商打包缺陷）

**现象**
```
Wrong line format PRDLIST_READ Cannot allocate fmatrix level 1 9999 -9
```
对 `test.pep_mhc` 全部 10 行逐行测试均失败，与输入内容无关。

**根本原因**：这是**上游打包错误**，不是使用问题。`-pmhc` 路径调用的子程序存在缺陷。

- `-p` 调用 `nnalign_..._allmhc_v3`（1153776 B，md5 `3287961878...`）→ 正常
- `-pmhc` 调用 `nnalign_..._v3`（1149640 B，md5 `b7b087197c...`）→ 有缺陷

**决定性验证**：把正常的 allmhc 变体覆盖到缺陷槽位上，`-pmhc` 立刻通过，输出与期望文件逐字节一致。

**已修复**：用正常变体覆盖缺陷槽位（原文件备份为 `..._v3.orig`）。修复后 vendor 测试通过。

---

### 问题 3：netMHCpan `-pmhc -context` 无法修复，提供等价入口

**现象**：修复问题 2 后，`-pmhc -context` 仍报 `Wrong line format PRDLIST_READ`。

**诊断**：`-pmhc -context` 路径中，子程序写出的中间文件第 3 列是**真实等位基因名**（如 `HLA-B07:09`），而父程序按 context 格式解析时期望的是 `ALL_MHC` 标签，字段数不匹配 → 必然报错。两个 nnalign 变体写出的内容相同，因此换二进制无效。

**解决方案**：提供等价入口 `netMHCpan_ctx`，把输入按第 3 列等位基因拆开，逐组用可正常工作的 `-p -context -a <allele>` 跑，再合并结果。

### 问题 4：netMHCstabpan `-ia` 缺 NetMHCpan-2.8

**现象**：`-ia` 报 `sh: 1: /tools/src/netMHCpan-2.8/netMHCpan: not found`，输出缺少 5 个亲和力列。

**原因**：启动器第 17 行写死指向 `/tools/src/netMHCpan-2.8/netMHCpan`——厂商开发机的绝对路径，且 NetMHCpan-2.8 **不在本次提供的文件里**。

**为什么不能直接用 4.2**：stabpan 用 `-ic50` 参数调用 2.8 的接口，4.2 无此参数，且两者的列序不同。

**已解决**：编写兼容层 `/opt/bio/compat/netMHCpan-compat`：
- 参数翻译：`-ic50` → `-BA`
- 列重排：从 4.2 输出提取 `Aff(nM)`、`%Rank_BA`，按 stabpan 期望的 5 列顺序重新格式化

**验证**（`-ia -p test.pep`）：
- 输出 14 列，`pos/HLA/peptide/Identity/Pred/Thalf(h)/%Rank_Stab/Exp_stab` 前 8 列与 `test.pep.out` **md5 完全相同**（`5eb90ebf483eb3b84dc93b4f521d4ad6`）
- 新增 5 列全部有真实数值，无报错

样例：
```

AAGLQDCTM  Pred=0.010  Thalf=0.15  %Rank_Stab=41.00 1-log50k=0.042  Aff=31626.61nM %Rank_aff=40.62 Combined=0.036
```

## 四、使用说明

### 基本用法

```bash
# 进入 WSL
wsl -d Ubuntu-24.04

# NetMHCpan：肽段 → MHC I 类结合预测
netMHCpan -a HLA-A02:01 -p peptides.pep
netMHCpan -a HLA-A02:01,HLA-A24:02 -p peptides.pep -BA
netMHCpan -hlaseq my_mhc.fsa -p peptides.pep      # 自定义 MHC 序列

# NetChop：蛋白酶体切割位点预测
netchop proteins.fsa

# NetMHCstabpan：半衰期 + 亲和力（-ia 开启亲和力列）
netMHCstabpan -a HLA-A02:01 -p peptides.pep
netMHCstabpan -ia -a HLA-A02:01 -p peptides.pep

# 带上下文（需 12 残基上下文窗口）
netMHCpan -p -context -a HLA-A02:01 -f context.txt
netMHCpan_ctx -f context_mhc.txt                   # 多等位基因 context
```

### `-pmhc -context` 输入格式注意

`netMHCpan_ctx` 的输入文件为「肽 + 上下文 + MHC」，用空格分隔：

```
SLYNTVATL AASLYNTVATLA HLA-A02:01
GILGFVFTL AAGILGFVFTLA HLA-A02:01
```

**关键约束**：上下文序列长度必须为 **12 个残基**（对于 9mer 肽段）。其他长度会静默返回 0 行结果——不是报错，容易踩坑。

## 五、已知限制

1. **`-pmhc -context` 需用 `netMHCpan_ctx`**：官方原生命令在此发行版中不可用（父程序字段解析与子程序输出格式不匹配）。数值结果等价，但输出格式与官方略有差异（按等位基因分组并带 `# ===== allele XXX =====` 分隔行）。

2. **`-ia` 走兼容层而非原生 2.8**：数值来自 NetMHCpan-4.2 而非 2.8，`1-log50k` 与 `Aff(nM)` 由 4.2 的 BA 预测换算，**与官方 2.8 的数值不会完全相同**。若论文需要与已发表的 NetMHCstabpan 1.0 结果严格对齐，需另行获取 NetMHCpan-2.8 替换兼容层。

3. **netchop 存在末位舍入差异**：如 0.931947 vs 0.931948，README 明确允许。

4. **`test.pep.out` 期望文件来自 `fixedcontext` 变体构建**（该目录本包不存在），但该项测试实际通过。
